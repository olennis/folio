# Folio 출시 체크리스트

App Store에 1.0을 올리기까지 남은 일. 끝낸 항목은 아래 "끝낸 일"로 옮긴다.
처음 정리한 날: 2026-11-18

## 남은 일

### A. 계정과 이름 — 직접 정해야 함

- [ ] **Apple Developer Program 가입** (연 129,000원 / 99달러)
  - 지금 맥에는 개발용 인증서(`Apple Development`)만 있고, 프로젝트에 `DEVELOPMENT_TEAM`이 없다.
  - 가입 후 Xcode → Signing & Capabilities에서 팀을 고르면 된다(서명 방식은 이미 Automatic).
- [ ] **App Store 이름 확인**
  - App Store 이름은 전 세계에서 하나뿐이라 "Folio"는 이미 쓰이고 있을 가능성이 높다.
  - App Store Connect에서 앱을 만들 때 확인하고, 막히면 "Folio – 앨범 사진첩"처럼 부제를 붙인다.
  - 홈 화면 이름(`CFBundleDisplayName = Folio`)은 App Store 이름과 달라도 된다.
- [ ] **번들 ID 확정** (지금 `dev.dh.sajincheop`)
  - 처음 올린 뒤에는 바꿀 수 없다. 예: `dev.dh.folio`.
  - 바꾸면 시뮬레이터·기기에 새 앱으로 깔려 기존 앨범 데이터가 보이지 않는다(출시 전이라 괜찮다).
  - 테스트 타깃(`.tests`, `.uitests`)의 번들 ID도 함께 바꾼다.

### B. 출시 전 보강

- [ ] **최소 iOS 버전 정하기** (지금 iOS 17.0)
  - 확인은 iOS 26.5 시뮬레이터에서만 했다.
  - iOS 17·18에서는 다른 코드로 도는 부분이 있다: 줌 전환(iOS 18+), 탭 바 검색 역할(18+), 미니 바(26.1 미만은 직접 띄움), 지명 찾기(26 미만은 `CLGeocoder`), Liquid Glass(26+).
  - 그 버전 시뮬레이터를 받아 시험하거나(Xcode → Settings → Components), 최소 버전을 iOS 18로 올리는 것을 권한다.
- [ ] **사진 아주 많이 넣기**: 한 번에 3,000장을 앨범에 넣으면 시뮬레이터에서 약 0.75초 동안 화면이 멈춘다.
  정리 탭에서 "전체 선택"으로 큰 묶음을 넣는 경우가 잦으면 백그라운드로 옮기고 진행 표시를 붙인다.
- [ ] **지명 기능 끄기 설정**(선택): 지금은 촬영 좌표를 Apple 지도 서비스로 보내 지명을 받는다(권한 문구와 개인정보 처리방침에 적음).
  민감하게 여기는 사용자를 위해 설정에서 끌 수 있게 하면 좋다.

### C. 실제 기기 확인 — 함께 해야 함

- [ ] **아이폰 실기기**: 카드 넘기기 스프링과 햅틱, 핀치 확대, 슬라이드쇼, 미니 바, 사진 "일부만 허용" 상태.
- [ ] **실기기 성능**: 사진 수천 장 보관함에서 정리 탭 열기, 큰 앨범 처음 열기, 추천이 뜨는 시간.
  아래 "성능 기준"의 시뮬레이터 수치와 비교한다.
- [ ] **화면에서 아직 못 본 흐름**: 정리 탭에서 사진을 앨범에 넣기, 앨범 선택 시트의 "추천" 구역, 홈의 "N년 전 이맘때".
  시뮬레이터 사진 6장이 모두 예시 앨범에 들어 있어 볼 수 없었다. 기기나 사진을 더 넣은 시뮬레이터에서 확인한다.
- [ ] **접근성과 화면 모드**: 다크 모드 전체 화면, 큰 글자(Dynamic Type 최대), VoiceOver로 앨범 만들고 사진 넣기.
- [ ] **TestFlight**: 내부 테스터로 며칠 써 보기.

## 성능 기준

`PhotoAlbumTests/PerformanceTests.swift`가 재고, 기준을 넘으면 실패한다. 시뮬레이터(맥) 수치.

| 경로 | 고치기 전 | 지금 |
|---|---|---|
| 사진 3,000장 앨범에 넣기 | 13.1초 | 0.75초 |
| 보관함 카드의 사진 수·표지 | 66ms (그릴 때마다) | 0.01ms 미만 |
| 3,000장 앨범 처음 열기 | 334ms | 38ms |
| 캐러셀 넘길 때 다시 그리기 | 334ms (넘길 때마다) | 0.001ms (저장해 둔 목록) |
| 앨범 부제(기간·장소) | 481ms (그릴 때마다) | 0.01ms 미만 |
| 앨범 추천 (앨범 20개, 6,000장) | 1.2초 (메인 스레드) | 20ms (백그라운드) |
| 몇 년 전 오늘 (같은 데이터) | 139ms (홈 그릴 때마다) | 7ms (백그라운드) |

바꾼 방식:
- 앨범의 사진 수·첫 사진·기간·대표 지명을 앨범에 저장해 두고, 사진이 바뀔 때만 `AlbumStore`·`PhotoMetadata`가 갱신한다.
- 정렬된 사진 목록은 저장소에 정렬해서 한 번에 조회하고, 화면은 앨범의 `revision`이 바뀔 때만 다시 구한다.
- 추천과 "몇 년 전 오늘"은 모든 사진을 훑지 않고 날짜·위치 조건으로 맞는 사진만 조회한다(`BackgroundQueries`). 계산량이 보관함 크기가 아니라 맞는 사진 수에 비례한다.
- 정리 탭의 미정리 사진 계산과 사진 넣기 때의 기존 사진 찾기는 한 번의 조회로 하고, 정리 탭은 백그라운드에서 구한다.
