# Folio 출시 체크리스트

App Store에 1.0을 올리기까지 남은 일. 끝낸 항목은 아래 "끝낸 일"로 옮긴다.
처음 정리한 날: 2026-11-18

## 남은 일

### A. 계정과 이름 — 직접 정해야 함

- [ ] **Apple Developer Program 가입** (연 129,000원 / 99달러)
  - 지금 맥에는 개발용 인증서(`Apple Development`)만 있고, 프로젝트에 `DEVELOPMENT_TEAM`이 없다.
  - 가입 후 Xcode → Signing & Capabilities에서 팀을 고르면 된다(서명 방식은 이미 Automatic).
- [ ] **App Store 이름 확인**
  - App Store 이름은 전 세계에서 하나뿐이라 "Folio"는 이미 쓰이고 있을 가능성이 높다.
  - App Store Connect에서 앱을 만들 때 확인하고, 막히면 "Folio – 앨범 사진첩"처럼 부제를 붙인다.
  - 홈 화면 이름(`CFBundleDisplayName = Folio`)은 App Store 이름과 달라도 된다.
- [ ] **번들 ID 확정** (지금 `dev.dh.sajincheop`)
  - 처음 올린 뒤에는 바꿀 수 없다. 예: `dev.dh.folio`.
  - 바꾸면 시뮬레이터·기기에 새 앱으로 깔려 기존 앨범 데이터가 보이지 않는다(출시 전이라 괜찮다).
  - 테스트 타깃(`.tests`, `.uitests`)의 번들 ID도 함께 바꾼다.

### A-2. Folio Pro 인앱 결제 — 계정이 생긴 뒤

앱 쪽 구현은 끝났다(`PhotoAlbum/Store/`). App Store Connect에서 다음을 해야 실제로 팔 수 있다.

- [ ] **유료 앱 계약(Paid Apps Agreement)** 동의, **은행 계좌와 세금 정보** 입력. 이게 없으면 인앱 결제 상품이 앱에 나타나지 않는다.
- [ ] **인앱 결제 상품 만들기**
  - 유형: 비소모성(Non-Consumable)
  - 상품 ID: `folio.pro` (`ProStore.productID`와 같아야 한다. 한 번 쓰면 다시 쓸 수 없다)
  - 가격: 5,900원 안팎(테스트용 `Folio.storekit`과 맞춰 둠). 이름 "Folio Pro", 설명은 `Folio.storekit`의 것.
  - 가족 공유: 켬(결제 화면이 "가족 공유로 함께 쓸 수 있어요"라고 안내한다. 끄면 문구도 고친다).
  - 심사용 스크린샷: 결제 화면(`mockup/screenshots/ui-14-paywall.png` 같은 화면을 실제 기기 크기로).
- [ ] **첫 버전과 함께 심사 제출**: 처음 만든 인앱 결제 상품은 앱 버전 심사에 함께 붙여 낸다.
- [ ] **샌드박스 테스터로 실기기 구매·복원 확인**(App Store Connect → 사용자 및 액세스 → 샌드박스).

무료와 Pro의 경계(바꾸려면 `ProStore.freeAlbumLimit`과 각 화면):
- 무료: 앨범 5개까지(이미 더 가진 앨범은 그대로 씀), 나머지 기능 전부.
- Pro: 앨범 무제한, 앨범 선택 시트의 "추천", 홈의 "추천 앨범"(몇 년 전 오늘, 자주 보는 인물),
  정리 탭의 "자동 분류"(연도·여행·장면. `PhotoAlbum/AutoClassify/`).
  비밀 앨범(앨범 메뉴의 "앨범 잠그기". `PhotoAlbum/Models/SecretLock.swift`): 열 때 Face ID(안 되면 기기 암호)를 묻고,
  앱을 떠나면 다시 잠긴다. 잠긴 앨범은 표지를 가리고 홈·추천·미니 바에 나오지 않는다.
  Pro가 사라져도 이미 잠근 앨범은 잠긴 채로 두고, 열거나 풀 수는 있다. 기기 암호가 없으면 갇히지 않게 그냥 연다.
  무료 사용자에게는 추천이 실제로 있을 때만 잠긴 미리보기를 보여 준다.

Xcode에서 결제를 눌러 보려면: Product → Scheme → Edit Scheme → Run → Options → StoreKit Configuration에서 `Folio.storekit`을 고른다.
공유 스킴에는 넣지 않았다. 넣으면 `xcodebuild test`로 단위·UI 테스트를 한꺼번에 돌릴 때 Xcode의 로컬 StoreKit 서버와
단위 테스트의 `SKTestSession`이 부딪혀 구매 테스트가 실패한다. 단위 테스트(`ProStoreTests`)는 스킴과 상관없이 이 파일로 구매·환불·복원을 확인한다.

### A-3. 자동 분류 — 실기기에서 확인할 것

- [ ] **장면 분류 정확도**: Vision 장면 분류는 시뮬레이터에서 돌지 않는다(`Failed to create espresso context`). 실기기에서 반려동물·음식·바다·산 제안이 맞는지 본다.
  틀린 사진이 많으면 `SceneCategory.minimumConfidence`(지금 0.6)를 올리거나 이름 목록(`SceneCategory.identifiers`)을 줄인다.
- [ ] **처음 분석 시간과 배터리**: 처음 한 번 보관함 전체를 분석한다(진행이 정리 탭에 "사진 살펴보는 중"으로 보임). 앱이 켜져 있는 동안만 돌고, 끊기면 다음에 이어 간다.
  수만 장이면 오래 걸릴 수 있다. 필요하면 충전 중 백그라운드 작업(`BGProcessingTask`)으로 옮긴다.
- [ ] **여행 기준**: 집(가장 많이 찍은 곳)에서 30km 넘게, 48시간 넘게 끊기지 않고, 12장 넘게 찍은 묶음. 실제 사진으로 보고 조정한다(`AutoClassifier.Thresholds`).
- 개인정보: 장면 분석은 기기 안에서만 하고, 결과는 앱 지원 폴더의 `scene-index.json`에만 둔다. 개인정보 처리방침에 적는다.
  여행 이름의 지명은 여행 가운데 좌표 한 점을 Apple 지도 서비스로 보내 받는다(사진 지명과 같은 방식).

### B. 출시 전 보강

- [ ] **최소 iOS 버전 정하기** (지금 iOS 17.0)
  - 확인은 iOS 26.5 시뮬레이터에서만 했다.
  - iOS 17·18에서는 다른 코드로 도는 부분이 있다: 줌 전환(iOS 18+), 탭 바 검색 역할(18+), 미니 바(26.1 미만은 직접 띄움), 지명 찾기(26 미만은 `CLGeocoder`), Liquid Glass(26+).
  - 그 버전 시뮬레이터를 받아 시험하거나(Xcode → Settings → Components), 최소 버전을 iOS 18로 올리는 것을 권한다.
- [ ] **사진 아주 많이 넣기**: 한 번에 3,000장을 앨범에 넣으면 시뮬레이터에서 약 0.75초 동안 화면이 멈춘다.
  정리 탭에서 "전체 선택"으로 큰 묶음을 넣는 경우가 잦으면 백그라운드로 옮기고 진행 표시를 붙인다.
- [ ] **지명 기능 끄기 설정**(선택): 지금은 촬영 좌표를 Apple 지도 서비스로 보내 지명을 받는다(권한 문구와 개인정보 처리방침에 적음).
  민감하게 여기는 사용자를 위해 설정에서 끌 수 있게 하면 좋다.

## 성능 기준

`PhotoAlbumTests/PerformanceTests.swift`가 재고, 기준을 넘으면 실패한다. 시뮬레이터(맥) 수치.

| 경로 | 고치기 전 | 지금 |
|---|---|---|
| 사진 3,000장 앨범에 넣기 | 13.1초 | 0.75초 |
| 보관함 카드의 사진 수·표지 | 66ms (그릴 때마다) | 0.01ms 미만 |
| 3,000장 앨범 처음 열기 | 334ms | 38ms |
| 캐러셀 넘길 때 다시 그리기 | 334ms (넘길 때마다) | 0.001ms (저장해 둔 목록) |
| 앨범 부제(기간·장소) | 481ms (그릴 때마다) | 0.01ms 미만 |
| 앨범 추천 (앨범 20개, 6,000장) | 1.2초 (메인 스레드) | 20ms (백그라운드) |
| 몇 년 전 오늘 (같은 데이터) | 139ms (홈 그릴 때마다) | 7ms (백그라운드) |

바꾼 방식:
- 앨범의 사진 수·첫 사진·기간·대표 지명을 앨범에 저장해 두고, 사진이 바뀔 때만 `AlbumStore`·`PhotoMetadata`가 갱신한다.
- 정렬된 사진 목록은 저장소에 정렬해서 한 번에 조회하고, 화면은 앨범의 `revision`이 바뀔 때만 다시 구한다.
- 추천과 "몇 년 전 오늘"은 모든 사진을 훑지 않고 날짜·위치 조건으로 맞는 사진만 조회한다(`BackgroundQueries`). 계산량이 보관함 크기가 아니라 맞는 사진 수에 비례한다.
- 정리 탭의 미정리 사진 계산과 사진 넣기 때의 기존 사진 찾기는 한 번의 조회로 하고, 정리 탭은 백그라운드에서 구한다.
